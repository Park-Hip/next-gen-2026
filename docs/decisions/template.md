# NNNN. Short title as a decision

- Status: Proposed | Accepted | Superseded by NNNN
- Date: YYYY-MM-DD
- Origin: Hiep | Hiep + AI | AI, accepted | AI, not reviewed
- Supersedes: ADR number or Mission 1 ID, or "None"; say what the old decision was in a few words, then its ID
- Issue: #N
- Research: `docs/research/NNNN-short-title.md`, or "None"

Write for a reader who does not know the code; code names and IDs go in Technical detail.

## In short

- **The problem:** what went wrong or was missing, with one concrete example from the simulated data.
- **The decision:** what the product does now.
- **What the employee sees:** the visible difference.
- **What we give up:** the cost or risk accepted.

## Context

What forced the decision: the problem, the constraint, or what was found while building.

## Options considered

1. **Option A** - one line on what it is.
2. **Option B** - the strongest alternative.

## Decision

The choice in one or two sentences.

## Reasons

Why it beats the strongest alternative, in Hiep's words.
An agent may only tidy wording Hiep gave; it never supplies the reasons.

## Consequences

What gets better, what gets worse, and what now has to be built or tested.

## Would change if

The observation that would reopen this decision.

## Evidence

The test cases, scripts or commits that show it works, and the evidence log line if AI shaped it.
Say in plain words what was checked; list file and test names in Technical detail.

## Technical detail

For the code owner: function and field names, enum values, config keys, file paths, test names, issue, PR and commit numbers, and gap, probe and promise IDs.
